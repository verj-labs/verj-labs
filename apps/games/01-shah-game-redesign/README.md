then a backend designed around what the game actually needs.

## Run it

Install Godot 4.7 (`brew install --cask godot`), then run `./run.sh` (or `./run.sh editor`). Or open `godot/project.godot` in the
editor and press F5, or from a terminal:

```bash
godot --path godot
```

## Test it

```bash
./test.sh          # all tests; prints failures and a summary, exit code 0 = all passed
./test.sh core     # only tests/core
./test.sh -v       # full output
```

Tests use gdUnit4 (vendored in `godot/addons/gdUnit4`). Write them to read like the rulebook,
e.g. `_legal("9H 9S", "10H 10S")` is a double 10 on a double 9. Rule ambiguities are tracked
in `docs/OPEN_QUESTIONS.md`.

## How to play (current build)

Menu -> Play vs Bots -> choose players (3-8), bot difficulty and game speed -> Start. Tap cards to select a
set of the same rank, then PLAY. PASS is only available when there is a pile. The game always
waits for you, even with nothing to play (press PASS; it turns yellow). You have 20 seconds
per turn on Normal (10 on Fast, 60 on Slow): when time runs out you pass, or, if you must lead, your lowest set is played for you.
Bots pause before each move, and the last play stays on screen for a moment when a round ends. When a game ends, NEXT GAME deals again, applies the card
exchange and the winner starts.

## Phone builds

The layout is 540 units wide (see `ui/ui_kit.gd`): buttons are at least 80 units tall, the smallest
pixel text is scale 3, and `ui/safe_margin.gd` keeps screens clear of the notch / Dynamic Island and
home bar. Needs the Godot export templates (Editor > Manage Export Templates, or the `.tpz` from the
Godot release page), plus Xcode for iOS and the Android SDK + JDK 17 for Android.

```bash
cd godot
godot --headless --export-debug "Android" builds/android/ShahExchange.apk   # shareable, debug-signed APK
godot --headless --export-debug "iOS" builds/ios/ShahExchange.ipa           # writes an Xcode project
open builds/ios/ShahExchange.xcodeproj                                       # pick your team, run on the phone
```

Delete `godot/builds/ios` before re-exporting iOS. Store assets:

```bash
python3 tools/make_icon.py && godot --headless --path godot -s ../tools/render_icons.gd     # app icon (iOS + Android)
godot --path godot --resolution 540x1170 -s ../tools/screenshots.gd -- --fake-notch          # store_assets/ screenshots
```

Production checklist: `docs/PRODUCTION_READINESS.md`. To preview a phone layout without a device:
`godot --path godot --resolution 450x975 -s ../tools/screenshot.gd -- res://scenes/game_table.tscn out.png players=4 wait=3 --fake-notch`.
The official 4.7.2 iOS template has no arm64 simulator library, so test iOS on a real device.

## Look and sound

The look is arcade on the outside (pixel font, neon colours, chunky panels) and clean where it
matters (cards keep a crisp cream face with vector suits). Everything is generated in code or by
script, with no downloaded fonts, images or sounds:

- `ui/pixel_font.gd` builds a 5x7 bitmap font at runtime; use it at whole-number scales.
- `ui/arcade.gd`, `ui/arcade_button.gd` make the notched-corner panels and buttons.
- `tools/generate_audio.py` (`python3 tools/generate_audio.py`) synthesises all chiptune sounds
  into `godot/assets/audio/`. Edit the numbers in a sound's function and re-run to change it.
- The MUSIC and SFX buttons (menu and table) switch each independently and remember the choice.

## Online play

```bash
./serve.sh                    # run the game server locally (port 8080)
python3 tools/check_server.py 8080   # independent smoke test of a running server
./run.sh                      # then: PLAY ONLINE, server ws://127.0.0.1:8080
```

Design, protocol and deployment notes are in `docs/ONLINE.md`.

## Layout

```
docs/GAME_RULES.md   source of truth for rules (copied from 01-shah-game; to be re-verified)
docs/OPEN_QUESTIONS.md  rule gaps and the decision the engine currently makes
godot/core/          pure game logic, no scene or node dependencies (testable, reusable on a server)
godot/bots/          bot players
godot/ui/            screens, card/hand views and the table controller (bots take turns here)
godot/scenes/        .tscn files (thin: each just attaches a ui/ script)
godot/tests/         gdUnit4 tests
```

## Ground rules

1. `core/` never touches nodes, scenes or timers: state + move in, new state or error out.
2. Rules come from `docs/GAME_RULES.md`, not from the old backend code.
3. Every rule gets a test before it gets UI.
